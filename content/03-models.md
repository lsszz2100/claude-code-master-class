Claude Code는 여러 Claude 모델 위에서 돌아갑니다. **어떤 모델을, 어느 강도로 쓰느냐**가 결과 품질·속도·비용을 좌우합니다. 이 챕터는 현재(2026년) 모델 라인업과, Claude Code에서 이를 통제하는 `/model`·`/effort`·`/fast`를 다룹니다.

| --- | --- | --- | --- | --- |
| **Claude Fable 5** | `claude-fable-5` | 1M | $10 / $50 | **최고 지능** — 장기 실행 에이전트, 가장 어려운 작업 |

| **Claude Sonnet 5** | `claude-sonnet-5` | 1M | $3 / $15※ | 속도와 지능의 최적 균형 |

> - **가장 어려운·장기 자율 작업** → **Fable 5** (최고 지능 티어)

## 모델 전환 — `/model`

세션 중 `/model`로 모델을 바꾸고 기본값으로 설정합니다.

```text
/model            # 대화형 선택
/model opus       # 별칭으로 바로 지정 (sonnet/opus/haiku/fable)
```

> **서브에이전트는 모델을 따로 지정**할 수 있습니다([7장](#ch7)의 `model` 프론트매터). 읽기 위주 탐색은 `haiku`로 저렴하게, 판단이 중요한 작업은 `opus`/`fable`로 — 리소스를 작업 성격에 맞추는 것이 핵심입니다.

## 추론 강도 — `/effort`

Claude 5 세대는 **effort**로 "얼마나 깊이 생각하고 행동할지"를 조절합니다. 단순히 사고량만이 아니라 도구 호출·검증 루프의 적극성까지 좌우합니다.

| 레벨 | 언제 |
| --- | --- |
| `max` | 정확성이 비용보다 훨씬 중요한 극난도 (과사고 위험, 테스트 후 사용) |
| `xhigh` | **어려운 코딩·에이전틱 작업** — 여기로 올려라 |
| `high` | **기본값** (Claude API·Claude Code). 지능·토큰 균형 |
| `medium` | 비용·지연 절감 — 품질이 유지되는 루틴 작업에 적극 활용 |
| `low` | 짧고 범위 명확한, 지연 민감 작업(채팅·단순 조회) |

```text
/effort xhigh
```

**effort를 지원하는 모델**은 Fable 5·Opus 5·Sonnet 5와 레거시 Opus 4.8·4.7·4.6, Sonnet 4.6 **뿐**입니다 — 그보다 이전 모델은 목록에 아예 없습니다. **Haiku 4.5는 effort도, 적응형 사고도 지원하지 않습니다** — 저비용·저지연이 이미 그 모델의 성격이라 조절할 레버가 없다고 보면 됩니다. 레거시 중 **Opus 4.6·Sonnet 4.6에는 `xhigh`가 없어** 지정해도 `high`로 내려앉습니다(에러가 아니라 조용한 폴백 — Claude Code는 지정한 레벨 **이하에서 가장 높은 지원 레벨**로 떨어뜨립니다. 올렸는데 안 달라졌다면 이걸 의심하세요). 기본값은 effort를 지원하는 모든 모델이 `high`인데, **Opus 4.7만 Claude Code 기본이 `xhigh`**입니다.

> **`/effort` 메뉴의 `ultracode`는 effort 레벨이 아닙니다.** 모델에는 `xhigh`를 보내고, 거기에 더해 Claude Code가 **동적 워크플로를 오케스트레이션**하도록 하는 Claude Code 쪽 설정입니다. 다른 레벨과 달리 **현재 세션에만** 적용됩니다.

> **이번 턴만 더 생각하게 하려면 `ultrathink`.** 프롬프트 아무 곳에나 `ultrathink`를 넣으면 Claude Code가 키워드로 인식해 그 턴에만 더 깊이 생각하라는 지시를 붙입니다 — **세션 effort 설정은 그대로**이고 API로 보내는 레벨도 안 바뀝니다. 반대로 **"think", "think hard", "think more"는 키워드가 아닙니다** — 그냥 평범한 프롬프트 텍스트로 흘러갑니다. 예전 Claude Code의 "생각 단계(think < think hard < think harder < ultrathink)"를 기억하고 있다면 지금은 `ultrathink` 하나만 남았다고 보면 됩니다.

> **effort는 "답변 길이" 레버가 아닙니다.** 사고량과 토큰 총량을 조절할 뿐이라, Opus 5에서는 effort를 낮춰도 눈에 보이는 응답이 안정적으로 짧아지지 않습니다. 답변을 짧게 만들고 싶으면 effort가 아니라 **프롬프트로 길이를 지시**하세요([14장](#ch14)).

> **핵심(2026 최신):** Opus 5·Sonnet 5의 기본 effort는 **`high`**입니다. **기본(high)에서 시작**해 자신의 평가셋으로 조정하세요 — **`low`·`medium`을 비용·속도의 주 레버로 적극 활용**하고(품질이 유지되는 한), **어려운 코딩·에이전틱엔 `xhigh`로 올립니다**. 이전 모델의 effort 기본값을 그대로 가져왔다면 재튜닝하세요.

- **낮은 effort에서 얕은 추론**이 보이면, 프롬프트로 우회하기보다 **effort를 올리는 것**이 먼저입니다.
- **높은 effort + 긴 작업**이면 출력 토큰 여유(`max_tokens`)를 넉넉히 — 사고가 예산의 큰 몫을 쓸 수 있습니다.

> **적응형 사고(adaptive thinking):** Opus 5·Sonnet 5·Fable 5는 언제·얼마나 생각할지 **스스로 정합니다**(고정 "thinking budget" 개념은 폐기). **Opus 5는 사고가 기본으로 켜져** 있고(이전 세대인 Opus 4.8·4.7은 꺼짐이 기본이었습니다), **Fable 5는 항상 켜져** 있어 끌 수 없습니다. effort가 그 깊이를 조절하는 주 레버입니다. 모델별 프롬프트 튜닝은 [14장 최신 모델 프롬프트 가이드](#ch14)에서 자세히 다룹니다.

## 빠른 모드 — `/fast`

**Fast 모드**는 Opus를 같은 지능으로 유지하면서 **출력 속도를 최대 2.5배**까지 올립니다(리서치 프리뷰). 작은 모델로 낮추는 게 아니라 같은 Opus를 더 빠르게 내보냅니다. Claude Code에서는 **Opus 5·4.8에서만** 쓸 수 있습니다 — Sonnet·Haiku에서 켜면 자동으로 꺼집니다.

```text
/fast     # 토글 — 인터랙티브하게 빠른 피드백이 필요할 때
```

> **Opus 4.7의 fast 모드는 2026-07-24에 제거됐습니다.** 그런데 Claude Code는 4.7을 여전히 fast 모델로 취급해서 **토글은 켜지지만 API가 요청을 거부**합니다 — 조용히 표준 속도로 도는 게 아니라 실패합니다. 4.7에서 fast를 쓰던 설정이 남아 있다면 Opus 5나 4.8로 옮기세요. **같은 "미지원"이라도 실패 방식이 다릅니다** — Opus 4.6은 fast를 요청해도 조용히 표준 속도로 돌고 표준 요금으로 청구되지만, 4.7은 요청 자체가 거부됩니다.

**비용을 반드시 알고 켜세요.** fast 모드는 백만 토큰당 **$10 / $50** — 표준 Opus($5/$25)의 **정확히 2배**입니다. 그리고 두 가지가 더 있습니다.

- **구독 요금제(Pro·Max·Team)에서도 fast는 플랜에 포함되지 않습니다.** 플랜 사용량이 남아 있어도 **사용량 크레딧에서 첫 토큰부터** fast 요금으로 빠져나갑니다. 크레딧이 꺼져 있으면 아예 못 씁니다.
- **대화 중간에 켜면 그 시점의 전체 컨텍스트를 fast 미캐시 입력가로 한 번 다시 냅니다.** 깊이 들어간 세션일수록 비싸므로, 쓸 거면 **세션 시작 때** 켜는 편이 쌉니다(껐다 켜도 이 비용은 한 번만 듭니다).

VS Code 확장에서는 지원하지 않고, Bedrock·Google Cloud·Foundry에서도 쓸 수 없습니다.

## 컨텍스트·비용 함께 보기

- **컨텍스트 창**: Fable 5·Opus 5·Sonnet 5는 **1M 토큰**(기본이자 최대), Haiku 4.5는 200K. 크다고 다 채우라는 뜻은 아닙니다 — 찰수록 성능이 떨어지므로 [자동 압축·`/clear`](#ch2)와 [컨텍스트 엔지니어링](#ch12)으로 관리하세요.
- **비용 통제**: `/usage`로 사용량·비용 확인. 저비용이 필요하면 **effort를 low/medium으로** 내리거나 모델을 낮추고(Sonnet/Haiku), 반복 컨텍스트가 크면 프롬프트 캐싱이 자동으로 절감합니다.
- **세션 중간에 모델을 바꾸면** 프롬프트 캐시가 무효화됩니다. **effort를 바꿔도 마찬가지**입니다 — effort가 프롬프트 구성에 반영되기 때문입니다. 둘 다 잦은 전환보다 작업 성격에 맞춰 초반에 정하는 편이 낫습니다.

```mermaid
flowchart TD
    Q{"작업 성격은?"}
    Q -->|"복잡한 코딩·에이전틱"| O["Opus 5 · high~xhigh"]
    Q -->|"가장 어려운·장기 자율"| F["Fable 5"]
    Q -->|"속도·비용 균형"| S["Sonnet 5 · high"]
    Q -->|"단순·빠름·저렴"| H["Haiku 4.5"]
```

## 핵심 요약

- 현재 라인업: **Fable 5**(최고 지능) · **Opus 5**(복잡 코딩·에이전틱, Anthropic 권장 기본) · **Sonnet 5**(균형) · **Haiku 4.5**(빠름·저렴). Opus 4.8 등은 레거시.
- **`/model`**로 모델을, **`/effort`**로 추론 강도를 조절 — **기본은 `high`, 어려운 코딩·에이전틱은 `xhigh`, 비용 절감은 `low/medium`**.
- **`/fast`**는 Opus 5·4.8을 최대 2.5배 빠르게. 단 **가격이 2배**이고 **구독 요금제에도 포함되지 않아** 사용량 크레딧에서 빠진다. 적응형 사고는 스스로 사고량을 정하고, **Haiku 4.5는 effort·적응형 사고 대상이 아니다.**
- 1M 컨텍스트라도 관리가 필요하고, 모델별 프롬프트 튜닝은 [14장](#ch14)에서 다룬다.
